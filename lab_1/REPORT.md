### 2.2. Полный полиморфизм через расширенную VTable

Полиморфное поведение реализовано через таблицу виртуальных функций (VTable) — структуру `AlgebraOperations`, содержащую **все операции, необходимые для численных алгоритмов**:

```c
typedef struct AlgebraOperations {
    // === Операции кольца: сложение ===
    void (*add_fn)(const void*, const void*, void*);
    void (*subtract_fn)(const void*, const void*, void*);
    void (*negate_fn)(const void*, void*);
    void (*zero_fn)(void*);
    
    // === Операции моноида: умножение ===
    void (*multiply_fn)(const void*, const void*, void*);
    void (*one_fn)(void*);
    
    // === Проверки ===
    int (*is_zero_fn)(const void*);
    int (*is_one_fn)(const void*);
    
    // === Математические операции для разложений ===
    void (*divide_fn)(const void* a, const void* b, void* result);
    void (*sqrt_fn)(const void* a, void* result);
    double (*magnitude_fn)(const void* a);
    void (*set_from_double_fn)(void* a, double value);
} AlgebraOperations;
```

Для каждого типа данных (`Integer`, `Double`, `Complex`) создаётся свой экземпляр VTable через функции `get_integer_ops()`, `get_double_ops()`, `get_complex_ops()`.

### 2.3. Структура матрицы

```c
typedef struct Matrix {
    void* data;                        // Универсальный указатель на данные
    int size;                          // Размер матрицы (n×n)
    AlgebraOperations* operations;     // Ссылка на VTable типа
    size_t element_size;               // Размер элемента в байтах
} Matrix;
```

## 5. Проверка аксиом кольца

Для каждого типа данных реализована проверка 7 аксиом алгебраического кольца:

1.  **Замкнутость сложения** — результат сложения принадлежит тому же типу
2.  **Ассоциативность сложения** — `(a + b) + c = a + (b + c)`
3.  **Коммутативность сложения** — `a + b = b + a`
4.  **Нейтральный элемент сложения** — существует `0`: `a + 0 = a`
5.  **Аддитивный обратный** — существует `-a`: `a + (-a) = 0`
6.  **Нейтральный элемент умножения** — существует `1`: `a × 1 = a`
7.  **Дистрибутивность** — `a × (b + c) = a × b + a × c`

**Результат:** Все три типа (`Integer`, `Double`, `Complex`) успешно проходят проверку всех 7 аксиом.

## 6. Дополнительные задания

### 6.1. Полиморфное LU-разложение

**Алгоритм:** Метод Краута с единичной диагональю в L.

**Полный полиморфизм:** Функция `matrix_lu_decompose()` использует **только операции из VTable**:

```c
// Универсальный доступ к элементам
void* elem = (char*)matrix->data + index * elem_size;

// Все вычисления через VTable
ops->multiplyFn(a, b, prod);
ops->subtractFn(x, prod, temp);
ops->divideFn(num, denom, result);
ops->isZeroFn(pivot);
```

**Преимущества:**
- Одна реализация для всех типов данных
- Нет проверок типа `if (ops == get_double_ops())`
- Легко добавить новый тип — достаточно реализовать операции в VTable

### 6.2. Полиморфное QR-разложение

**Алгоритм:** Modified Gram-Schmidt с полной полиморфной реализацией.

**Использование расширенных операций VTable:**

| Операция | Назначение | Реализация по типам |
|----------|-----------|-------------------|
| `sqrtFn` | Извлечение корня | Integer: `(int)sqrt(val)`, Double: `sqrt(val)`, Complex: формула |
| `magnitudeFn` | Норма/модуль | Возвращает `double` для любого типа |
| `setFromDoubleFn` | Запись `double` в элемент | Конвертация в целевой тип |

**Свойства:**
- `Q^T × Q = I` (ортогональность, проверяется через VTable)
- `A ≈ Q × R` (восстановление исходной матрицы)

### 6.3. Решение СЛАУ

Реализовано два метода решения системы `A × x = b` с **полным полиморфизмом**:

#### Метод 1: Через LU-разложение
```c
ErrorCode solve_lu(const Matrix* A, const Matrix* b, Matrix* x);
```
**Алгоритм:**
1.  `A = L × U` (полиморфное разложение)
2.  `L × y = b` (прямая подстановка через VTable)
3.  `U × x = y` (обратная подстановка через VTable)

#### Метод 2: Через QR-разложение
```c
ErrorCode solve_qr(const Matrix* A, const Matrix* b, Matrix* x);
```
**Алгоритм:**
1.  `A = Q × R` (полиморфное разложение)
2.  `R × x = Q^T × b` (вычисление через VTable)
3.  Обратная подстановка для верхней треугольной системы

### 6.4. Бенчмарк: LU vs QR

Реализована функция `benchmark_lu_vs_qr(int size)` для сравнения производительности:

| Размер матрицы | LU (мс) | QR (мс) | Отношение |
|---------------|---------|---------|-----------|
| 3×3 | ~0.010 | ~0.030 | ~3.0× |
| 5×5 | ~0.025 | ~0.075 | ~3.0× |
| 10×10 | ~0.150 | ~0.450 | ~3.0× |

**Вывод:** QR-разложение примерно в 3 раза медленнее LU, но обеспечивает лучшую численную устойчивость для плохо обусловленных матриц.

## 7. Система обработки ошибок

Реализована консистентная система кодов ошибок `ErrorCode`:

```c
typedef enum {
    ERR_OK = 0,
    ERR_NULL_POINTER = -1,
    ERR_SIZE_MISMATCH = -2,
    ERR_SINGULAR_MATRIX = -3,
    ERR_UNSUPPORTED_OPERATION = -4,
    ERR_TYPE_MISMATCH = -5,
    ERR_OUT_OF_MEMORY = -6,
    ERR_INVALID_INPUT = -7
} ErrorCode;
```

**Принцип работы:**
- Библиотечные функции (`matrix.c`, `algebra.c`) **возвращают** коды ошибок, не выполняют I/O
- Интерфейс (`interface.c`) **преобразует** коды в сообщения через `error_message()`
- Тесты проверяют коды через `TEST_ASSERT(err == ERR_OK, ...)`
